## westock 主题/成份链路本地缓存工具（新建）

**背景**：用户问 westock 的主题和成份链路能否下载为本地缓存。

**结论/踩点**：
- westock CLI **没有内置导出或缓存开关**（全局 flag 只有 `-h/-v`，无 `--format json` / `--output`）；输出是结构化 Markdown 表格，只能 `stdout` 重定向 + 解析。
- 相关命令：`westock industry-chain list`（183 个产业链主题，PRD 前缀代码）、`industry-chain graph <主题名>`（`--category upstream/midstream/downstream`）、`industry-chain stock <代码>`、`sector ranking --kind concept`（804 个概念板块，pt 代码）、`sector constituent <pt代码>`（支持逗号批量，但**批量返回结果无法按板块拆分**，所以缓存时只能逐板块单查）。
- 图谱 Markdown 为「续行」结构：同一只股票的多个节点写在后续行，股票代码列为空 → 解析时必须继承上一行的股票。

**产物**：
- 脚本 `D:/mystock/_ws_chain_cache.py`（stdlib only，`--mode chain|concept|all`、`--limit`、`--workers`、`--force`、`--date`、`--no-export`；按 snapshot 日期天然增量，raw md 落盘可重解析）。
- 数据 `D:/mystock/data/westock_cache/`：SQLite `westock.db`（28MB，表 meta / chain_topics / chain_stock_node / concept_sectors / concept_stocks）+ `csv/` + `raw/chain/*.md`。
- 首次全量结果：183 主题 → 141,127 条「主题-节点-个股」关系（覆盖 5091 只票）；804 概念板块 → 102,923 条板块成份关系（覆盖 5572 只票）。耗时 9 分钟（workers=8）。

**用途**：涨停/题材归因时可离线反查「个股 → 所属主题/概念」，或「主题 → 成份股列表」，避免每条都打接口。
