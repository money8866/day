## V10.2 选股数据完全移出仓位计算（11-02 08:17~）

### 设计原则
环境模块回答「这个市场该拿多少仓」，选股模块回答「买哪几只」。
两者此前互相绑架 —— `stock_picks.db` 只覆盖 20260601 起，
导致 1~5 月 132 天的环境判断全部失真为 0% 仓位。

### 四处剥离
1. **`calculate_target_position` 移除「合格机会数量」上限**
   原：无合格买点 → cap=0；买点不足 → 按比例缩减
2. **`full_position_authorization` 移除第 6、7 项**
   「合格个股数量充足」「个股买点质量」→ 检查项 11 减为 8，全为市场环境层面
3. **`plan_ladder_add` 的「出现有效买点」降级为提示项**
4. **组合风险预算改用 ETF 波动率代理**（关键一环）

### ⭐ 组合风险的解耦（最容易漏的一环）
风险预算要算「各持仓潜在止损损失之和」，原本取**个股止损价**（选股库）。
改用 `etf_mainline.estimate_market_volatility()`：
用行业 ETF 的**日均绝对涨跌幅**作为典型止损距离的代理
（实测 70 只 ETF 近 60 日日均绝对涨幅：中位 1.21%，区间 0.63%~2.58%；
止损距离 = 中位 × 2.5，夹在 [3%, 12%]）。
风险敞口 = 单股上限 × 代理止损距离 → 与「今天有几只票」完全无关。

⚠️ 若只做前 3 项而不改组合风险，仍会漏：
同一状态下合格标的 0 只 vs 5 只得出 **60% vs 43%** 的不同仓位
（等权单股权重随标的数变化 → 风险不同 → 仓位不同）。
`test_decoupling.py::test_target_position_independent_of_qualified_count` 抓到了这个。

## V10.5 修复：盘中 20% vs 盘后 5% 不一致（11-02 16:40~17:30）

**用户反馈**：「为什么盘后运行的结果又是 5%，和盘中最终不一致，请检查算法和数据」

### 两个独立根因（叠加导致）

#### 根因 1：投票链持久化断链（状态机被冻结）
**症状**：11/02 盘后状态 = S3，权限 5%，核心证据「恐慌加速持续」。
但节点判定明确是 `SELLING_PRESSURE_EASING`（S4），广度 85.1%、涨停 125、跌停 10。

**根因**：`market_regime_v101.py:1902` 调用 `v10.save_state(trade_date, dec, node.node_type)`
**漏传 `vote_history` 参数** → save_state 默认 None → 写库为 `[]`。
→ 每次盘后运行都把投票链清空 → 次日 `prev_votes` 永远为空
→ 窗口内永远只有「今日 1 票」→ `min_votes=2` 永不达标
→ **状态机永久冻结在 prev_state**。

**证据**：
```
regime_state 表：
  20261030  S3  PANIC_ACCELERATION       vote_history=[]        ← 应为 ["S3"]
  20261102  S3  SELLING_PRESSURE_EASING  vote_history=["S4"]    ← 链已断，只1票
重算 10/30 → vote_history=['S3']（库里的 [] 是错的）
```

**修复（两层）**：
1. `v101.py` 补传 `getattr(dec,'vote_history',None)`
2. **自愈机制** `market_regime_v10.rebuild_vote_history()`：
   链断时（prev 存在但 prev_votes 为空）从历史数据逐日重算节点投票，不依赖持久化。
   `state_machine.auto_rebuild_votes=true`

#### 根因 2：盘中与盘后是两套独立逻辑
盘中 `_intraday_monitor.py` 用**自定义启发式**：
```python
if breadth_pass and ml.get('industries'):  state_guess='S5'; cap=40
elif c_breadth_zt and c_breadth_dt and ma5>=ma20: state_guess='S4'; cap=20
else: state_guess='S3'; cap=5
if prev_state=='S3' and ratio>0.60: cap=max(cap,mode_s3s)  # 历史众数
```
盘后用 V10.1 状态机 + 权限表 → **必然分叉**。

**修复**：盘中新增 `_state_via_v10()`：
1. 用昨日收盘快照做底（指数、成交额等盘中拿不到的沿用昨日）
2. 用实时数据覆盖 breadth(ratio/delta/_hist) + limit(zt/dt/promo/strong)
3. 跑**真实的** V10.0 `detect_market_nodes` + `decide_state`
4. 用**真实的** V10.1 `position_authority` 取权限
→ 盘中与盘后同一套判定，差异只来自数据时效性。

#### 根因 3（连带发现）：快照把当天当成昨天
盘后重跑后今天有报告了 → `pvs.build()` 取"最新有报告的交易日"= 今天
→ 「昨日涨停名单」= 今日涨停名单 → **晋级率恒 100%**、强股表现恒 +11%。
**修复**：`build(before_date=...)`，盘中传 `before_date=trade_date`。
