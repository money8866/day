
## 10-11 08:25 「极致缩量」落地检查：发现只落地一半，已补齐

用户问「极致缩量落地为代码了吗」→ 核查发现 `daily_picker.py` 里 **0.6 这个阈值是硬编码的，
没进参数区，且极缩量没有额外加分** —— 即只做了"档位标注"，没做"优先级"。

### 已补齐
1. `vol_ratio_extreme = 0.6` 提为参数（原硬编码 `if vol_ratio < 0.6`）
2. 极缩量**额外加 15 分**（基准量比分 35 → 35+15=50）
3. **强制排在候选池最前**（二级排序：先看极缩量，再看分数）
4. 输出标 `★` + 单独汇总「★ 极缩量 N 只」
5. 新增 `--extreme-only`（只看量比<0.6）、`--max-vol`（临时改门槛）
6. 档位划分修正：原代码 `elif vol_ratio < 1.0` 后又接 `elif vol_ratio < strong(1.0)`
   —— **是死分支**，且漏了 0.9~1.0 区间。现改为 0.6/0.9/1.0 三档，与回测档位对齐

### 量比打分验证（满分50）
0.40→40.7 / 0.80→16.3 / 0.95→12.8 / 1.20→7.0 / 1.40→2.3（区分度明显）

### 顺带改的：空仓原因可读性
原输出只说"无符合条件的标的"，无法区分"没缺口"还是"有缺口但量比不合格"。
现输出：
- `ⓘ 全市场当日无符合条件的上跳缺口（精确命中 0 只）→ 属正常现象`
- `ⓘ 有 N 只命中缺口，但量比均 ≥ X（放量剔除）→ 今日属「有缺口但无缩量」`

### 实测（10-11 周五）
中证1000 二十日 −5.84%（回调期满足），但**精确缺口仅命中 3 只且量比全部 ≥1.5 → 空仓**。
程序逻辑正确，是当日无机会。

### 经验
「落地」不等于「加了判断」——档位标注只影响展示，
优先级必须体现在**打分 + 排序**上才真正影响输出。
核查已有实现时要问：这个东西改变了输出顺序/内容吗？
