### 定位到的五个问题（任务第二步）

**问题 1：广度低位被直接解释为底部 —— 确认存在**
- `position_engine_v95.py::_is_weak_veto`：`up_ratio < 35%` → 一票否决，强制 0~15% 仓位。广度低位被当成"必须完全空仓"的二值判断，**没有区分"恐慌加速（卖压扩大）"与"情绪极端（可能接近底部）"**
- V9.0 L3 的 `mom_state="急杀"` 直接映射为 D6 下跌防守
- V9.9 的位置分位 `pos_pct>=80 → cap×0.7`（高位扣分）与 `pos_pct` 低位无对应处理 —— **低位不会自动加分，这是对的；但也没有"卖压是否衰减"的独立判断**

**问题 2：量比与全市场成交额混用 —— 确认存在**
- `position_engine_v95.py::_judge_liquidity_env` 用的 `l6_liquidity.details['amount_ratio_5_20']` 是**指数成交量比**
- 报告里却与 `overview['total_amount']`（**全市场**日线成交额求和）并列展示，读者会误认为同源
- `calc_sentiment_score` 的「量能结构」同样用指数 `df['vol']`

**问题 3：位置分位口径 —— 部分明确但与要求不符**
- 改造前新增的是 60 日分位 + 120 日波动率分位
- 任务要求：250 交易日收盘分位 + 回撤幅度历史分位 + 相对 MA20/MA60 位置
- 指数K线窗口只有 180 自然日，**250 日分位当时算不出来**

**问题 4：D 日计数歧义 —— 确认存在且严重**
- `_judge_dday` 把 `(mom_state, sentiment_state)` 映射成 D2~D7 —— **这是「动量状态 × 情绪状态」的组合标签，不是连续天数**
- 但 `_build_short_term_hint` 输出「D1-D2：确认后小仓位试错」「D3：首分低吸重点窗口」「D6-D7：下跌防守」
- 报告写「节奏：D6 下跌防守」→ **极易被读成"连续下跌6天"**
- 附带问题：**D1 根本不存在**（`_judge_dday` 永不返回 1），但 hint 里写了"D1-D2"

**问题 5：目标仓位 / 实际仓位 / 加仓空间混淆 —— 确认存在（已按用户要求简化）**
- `PositionV99Result` 有 `position_target` 和 `add_room`（= `confirm_cap - target`），但**没有"当前实际仓位"字段**
- `prev_pos` 来自 DB 上一日的**目标**仓位 —— 等于把"昨天的目标"当成"当前实际持仓"
- `add_room` 语义是"距确认上限还有多少"，不是"还能加多少"
- 报告的【仓位建议】只有目标与空间，**没有实际仓位**，用户无法知道偏离

> **处理方式（2026-10-31 用户决定）**：既然「实际仓位」本模块拿不到、
> 「加仓空间」语义又容易误解，**直接删掉这两个概念，只保留「建议目标仓位」**。
> 见本文档「六、后续调整」章节。

## 三、第四步：实现要点

### 3.1 指标口径（全部写明并可追溯）

| 指标 | 口径 |
|---|---|
| 市场广度 | `上涨家数 / (上涨家数 + 下跌家数)`，**平盘家数单列不参与分母**，另存 `total_based_ratio` 备用 |
| 涨跌停 | 收盘价判定：688/300/301/8/92 → 20%，其余 → 10%。**ST 股 5% 无法从 daily_cache 识别**，记为口径局限 |
| 炸板率 | `炸板 / (封住 + 炸板)`，炸板来自 `limit_list_d` 的 `limit=='Z'` |
| 连板晋级率 | **真实计算**：昨日涨停股中今日继续涨停的比例 |
| 昨日涨停股次日表现 | **真实计算**：昨日涨停名单在今日的平均涨幅与上涨比例 |
| 全市场成交额 | `daily_cache` 全市场 `amount` 求和（千元→亿元） |
| 位置分位 | 收盘价在最近 **250 个交易日 [最低,最高]** 区间中的位置；各指数独立计算 |
| 回撤分位 | 当前 20 日最大回撤在过去 250 日各 20 日回撤中的分位 |
| 相对强弱 | `中证2000 涨跌幅 - 沪深300 涨跌幅`（各自独立序列） |
| 尾盘承接 | **UNKNOWN**（无分钟数据） |

### 3.2 节点识别（多指标联合，输出证据）

| 节点 | 触发条件 | 含义 |
|---|---|---|
| `PANIC_ACCELERATION` 恐慌加速 | 广度<20% / 跌停放大1.5倍或≥30只 / 指数跌且成交额较20日均额放大>15% / 小盘弱于大盘>1pp / 昨日涨停股今日均值<-2%，**满足≥3 项** | 风险快速释放，**尚不能认定接近底部** |
| `EXTREME_SENTIMENT` 极端情绪 | 广度处历史10%分位以下 / 跌停处历史90%分位以上 / 炸板率>60% / 晋级率≤20% / 强势股均值<-2%，**满足≥2 项** | 可能进入情绪极端区，**不等于底部、不等于买点** |
| `SELLING_PRESSURE_EASING` 卖压衰减 | 跌停明显减少 / 广度较前日回升≥8pp / **指数跌幅收窄** / 强势股负反馈减弱 / 炸板率≤35%，**满足≥2 项** | 卖压可能衰减，**尚未确认修复** |
| `REPAIR_CONFIRMED` 修复确认 | **指数趋势 + 市场广度 + 短线情绪三方面同时成立**（站上MA20且收涨 / 广度≥55%且回升≥10pp / 跌停减少为必要条件+另一条情绪佐证），**满足≥3 项** | 环境开始支持重新评估仓位 |

> ★ 卖压衰减**刻意不含"接近近期低点"**：那是**状态**不是**变化量**，熊市中天天成立，会把该节点变成常态（见第五节踩坑）。

### 3.3 五状态机（统一转移模型）

```
每日先算「今日应处于的状态」target，再用连续天数确认决定是否真的切换：
  同一状态          → 直接保持，连续天数 +1
  切出风险态(S3/S4/S5) → 需连续 exit_days 日无风险节点（风险解除不能仅依赖单日反弹）
  其余切换          → 需连续 confirm_days 日匹配
  S3 恐慌加速      → confirm_days=1，允许极端行情快速风险升级
```
确认计数用 `pending_target + pending_days` 持久化在 `market_regime_v10.db`。

### 3.4 仓位建议（严格三分）

| 状态 | 目标仓位 | 允许试探 |
|---|---:|---|
| S1 正常 | 按现有策略（无统一目标） | 是 |
| S2 退潮 | 30% | 否 |
| S3 恐慌加速 | 5%（上限 5%） | 否 |
| S4 卖压衰减 | 5%（上限 5%） | 否 |
| S5 修复确认 | 20% | 是（**仅个股信号成立时**） |

- **只输出「建议目标仓位」** —— 不涉及实际持仓，不计算加仓空间（2026-10-31 用户决定）
- 所有状态都附加「加仓必须满足的条件」，首条固定为「个股原有买入信号成立」
- 「加仓必须满足的条件」讲的是**个股信号层面的前置条件**，不是"账户还能加多少"

## 十、后续调整：仓位建议简化为「只给建议目标仓位」

**日期**：2026-10-31（用户要求）

### 用户诉求
> 不需要实际仓位和允许加仓空间，有建议目标仓位就够了

### 为什么这样改是合理的
1. **「当前实际仓位」本模块根本拿不到** —— V10.0 是环境判断模块，不是账户管理模块。
   硬要一个「实际仓位」入参，只会把上一日的*目标*仓位当成实际持仓（正是问题 5 的根源）。
2. **「允许加仓空间 = 目标 - 实际」在语义上是空的** —— 账户能不能加仓取决于你的
   持仓成本、可用资金、单一标的集中度，这些都不在行情数据里。
3. **V9.9 的 `add_room` = `confirm_cap - target`** —— 语义是"距确认上限还有多远"，
   不是"还能加多少"，本来就有误导性。

### 实际改动

| 文件 | 改动 |
|---|---|
| `market_regime_v10.py` | `PositionAdvice` 删 `actual_position` / `add_room` / `excess_note`；<br>`suggest_position()` 去掉 `actual_position` 入参；<br>`analyze_trade_date()` 去掉该参数；<br>报告删「当前实际仓位」「允许加仓空间」两行；<br>CLI 删 `--actual-position`；JSON 删 `actual` / `add_room` |
| `position_engine_v95.py` | `PositionV99Result` 删 `add_room` 字段与计算；<br>报告「当前目标：x%   可加仓空间：y%」→「当前目标：x%」 |
| `test_market_regime_v10.py` | 删 3 个 actual/add_room/excess 用例，新增 2 个（无该字段 / 目标仓位必给出） |
| `tushare_quant.py` | 微信推送模板同步（去掉「可加仓空间：xx%」） |

### 保留的内容（仍有价值）
- **建议目标仓位** —— 唯一保留的仓位数字
- **当前是否允许主动试探** —— 环境层是否开放主动买入（对应「不因跌幅大而抄底」的约束）
- **建议动作** —— 状态对应的操作方向
- **加仓必须满足的条件** —— 注意这是**个股信号层面的前置条件**
  （「个股原有买入信号成立」），不是账户剩余空间
- **需要降低仓位的条件** —— 风险触发线
