## 三、第三步：三个独立核心模块

### 1. S6 强势主升识别（四个**独立**模块）

每个模块输出 `passed` + `evidence[]` + `confidence`，**不合并成单一总分**。

| 模块 | 检查项 | 关键约束 |
|---|---|---|
| A 指数趋势 | MA20/MA60 位置、近5/20日收益、近期回撤、参与指数数 | 不能单指数代表全市场（≥4 个）；**不使用分位**（位置低≠即将反转） |
| B 市场广度 | 上涨占比、5日/20日均广度、连续2日达标、涨跌停 | 单日 >55% **不足以**进 S6 |
| C 短线赚钱效应 | 涨停、跌停、炸板率、晋级率、昨日涨停股次日均值/上涨比例 | 区分"涨停数增加"与"实际赚钱效应改善" |
| D 主线持续性 | `lifecycle` ∈ {主升,启动,高潮,加速主升}、`mainline_type` ∈ {趋势主线,情绪+趋势共振}、`days_strong`≥2、趋势分、涨停数、上涨宽度 | **不得仅凭热度评分认定主线** |

`require_all_modules=true` → 四模块必须**全部**通过才进 S6。

### 2. 仓位权限（`position_authority`）

| 状态 | 权限上限 |
|---|---|
| S1 正常 | 60% |
| S2 退潮 | 30% |
| S3 恐慌加速 | 5% |
| S4 卖压衰减 | 10% |
| S5 修复确认 | 60% |
| S6 强势主升 | 100% |

★ **市场允许持有 100%，不代表系统必须持有 100%。**

### 3. 满仓授权（`full_position_authorization`）

十项必要条件，**任一不满足即不得授权**：

1. 市场状态为 S6　2. 指数趋势通过　3. 市场广度持续改善　4. 短线赚钱效应确认
5. 主线持续性通过　6. 合格个股数量充足（≥3）　7. 个股买点质量合格（风险收益比/止损距离）
8. 组合风险检查通过　9. 账户流动性允许　10. 核心数据完整

输出 `FULL_ALLOWED` / `FULL_DENIED` / `FULL_REVIEW`。
★ **数据缺失 → REVIEW 或 DENIED，绝不默认通过。**
★ 返回 ALLOWED 也**不等于**自动满仓 —— 实际建议仓位仍由 `calculate_target_position` 决定。

## 四、第四步：个股机会匹配 + 组合风险预算

### 个股机会分类（复用原系统，不重新设计信号）

从 `stock_pick` 读取，按 `action` 分三类：
- **合格买入信号**：BUY / 核心买点 / 可开仓·下蹲买点 / 放量突破后缩量回踩买点·CONFIRMED / RIGHT_BOTTOM / 优选 / 买点池
- **条件观察信号**：可开仓·下蹲待确认(半仓) / 观察 / 观察池 / 早鸟预警 / 跟踪·等待放量再突破 / WATCH
- **不满足买入条件**：WAIT / NO_CHASE / MIDLINE_HOLD

★ `horizon=mid` 的中线仓（rb_trend）**单独统计，不计入短线可部署仓位**。

每只合格股计算：止损距离、风险收益比、流动性、行业/主题归属。

### 组合风险预算

单股风险金额 = 持仓市值 × (止损距离 + 成本0.05% + 滑点0.15%)

| 约束 | 初始值 |
|---|---|
| 单股最大仓位 | 15% |
| 单主题最大仓位 | 35% |
| 单行业最大仓位 | 30% |
| 组合总风险预算 | 3.0% |
| 高相关组集中度 | 40% |
| 现金最低保留 | 10%（→ 仓位上限 90%） |

★ **组合风险预算与目标仓位冲突时，优先遵守组合风险预算**，按比例缩减目标仓位并输出限制原因。

## 五、第五步：分级加仓 + 满仓退出

### 分级加仓（`plan_ladder_add`）

阶梯 `20 → 40 → 60 → 80 → 100`（配置化），单次加仓幅度上限 20pp。

加仓前六项检查：市场状态维持 / 满仓授权未恶化 / 出现有效买点 / 组合风险仍合格 / 主线未变化 / 目标仓位支持本级。
★ 由**新的交易信号与风险检查**触发，不由固定时间间隔触发。

### 满仓退出（`full_position_exit_check`）

八种触发条件，按严重程度分级输出：

| 结果 | 含义 |
|---|---|
| `HOLD_POSITION` | 暂时维持，但**停止加仓** |
| `REDUCE_POSITION` | 降低仓位 |
| `EXIT_INVALID_POSITIONS` | 处理交易逻辑已失效的持仓 |

★ **市场环境恶化不等于所有股票必须同步卖出。**
★ 本模块只生成建议，**不擅自执行交易**。

## 八、必须如实说明的三个问题

### 1. 满仓授权：规则已实现，**效果尚未验证**

全样本 64 天中 `FULL_ALLOWED` **0 次**，`FULL_REVIEW` 34 次、`FULL_DENIED` 30 次。

原因不是 bug，是十项条件在 2026 年 7-10 月这段单边下跌市里**从未同时满足**（S6 本身 0 天）。
→ **没有任何样本外证据支持满仓机制的有效性**，也无法判断它是过严还是过松。
→ 按任务要求，标记为「**规则已实现、效果尚未验证**」。

### 2. S4 / S5 / S6 在回放期从未出现 —— 根因在 V10.0 层

V10.0 节点识别在这 64 天的分布：`PANIC_ACCELERATION` 9 天、`EXTREME_SENTIMENT` 4 天、
`SELLING_PRESSURE_EASING` **1 天**、`REPAIR_CONFIRMED` **0 天**。

S4 依赖卖压衰减节点、S5 依赖修复确认节点 → 节点本身罕见，状态自然罕见。
**这不是 V10.1 的缺陷，是继承自 V10.0 的真实历史分布。**

### 3. 10/23 真实强势日：S6 判定为「不通过」——但这是设计意图

20261023 是 2026 年 10 月最真实的强势日（广度 83.3%、短线赚钱效应 ✓、
主线「机器人」主升/连续强态 3 日/趋势分 91.0/龙头宇树科技 ✓），但**指数趋势模块否决**：

```
站上MA20 0/5（0%，要求 ≥60%）✗
站上MA60 0/5（0%，要求 ≥40%）✗
```

原因：9 月底到 10 月是单边下跌，10/23 时所有指数仍在 MA20 下方。
**这一天是「题材驱动的局部主升」，不是「指数级主升」。** 我的定义要求指数与个股共振 ——
这是刻意的保守设计，不是 bug。**没有为了让它通过而放松阈值。**
